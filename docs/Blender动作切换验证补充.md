# Blender 动作切换验证补充

本文档补充说明：在 Blender 中，当前主骨架已经可以从 `idle` 切换到 `response`，并驱动“已附好材质的会动模型”一起播放响应动作。

## 1. 当前已验证结论

已经确认：

1. 主骨架 `Armature` 可以正常播放 `idle`
2. 当前最终显示模型已经成功附上原始材质
3. 主骨架可以切换到 `response`
4. 切换后，当前最终显示模型会一起播放 `response`

这说明当前资产已经进入可继续导出多动画 `GLB` 的状态。

本步骤对应一张操作截图，截图核心意思如下：

1. 当前选中的是主骨架 `Armature`
2. 底部已切到 `Action Editor（动作编辑器）`
3. 在当前动作名左侧的小下拉切换位置，可以切换动作
4. 当前动作已经显示为 `response`

## 3. 实际操作步骤

1. 选中主骨架 `Armature`
2. 切到 `Action Editor（动作编辑器）`
3. 在当前动作名左侧的小下拉切换区域切换动作
4. 从 `idle` 切换到 `response`
5. 播放时间轴
6. 观察当前“会动且已附材质”的模型是否一起播放 `response`

## 4. 成功标准

如果满足下面两点，就说明这一步已经跑通：

1. 主骨架 `Armature` 能在同一个骨架上切换 `idle` 和 `response`
2. 当前最终显示模型会跟着一起播放 `response`

## 5. 当前阶段意义

这一步的意义很大，因为它说明当前路线已经不是“只有一个待机动作的单动画模型”，而是已经具备：

1. 一个主骨架
2. 至少两条可切换动作
3. 可继续整理成最终导出的多动画 `GLB`

下一步就可以继续做：

1. 清理不再需要的重复对象
2. 固化最终导出结构
3. 导出一个带材质、带多条动画的最终 `GLB`

## 6. 如果某一帧脸部突然拉伸，优先按“资产问题”排查

当前新增一个明确判断：

1. 如果是“只有某一帧”脸部突然被拉长、扯坏、爆开
2. 而不是整段动作都持续变形

那么优先怀疑的不是网页播放逻辑，而是 Blender 里的动作数据或绑定数据。

尤其像“第 20 帧会拉伸”这种现象，通常说明：

1. 第 20 帧附近存在异常关键帧
2. 某个面部相关骨骼在这一帧旋转/位移/缩放异常
3. 这一帧混入了不该有的缩放
4. 模型上仍残留了错误权重、约束或 shape key 驱动

## 7. 推荐排查顺序

### 7.1 先确认是不是 Blender 里就已经坏了

先不要急着导出网页测试，先在 Blender 里直接验证：

1. 选中主骨架 `Armature`
2. 切到 `response`
3. 把时间轴停到第 20 帧
4. 直接在 Blender 视图里看脸部是否已经拉伸

如果 Blender 里第 20 帧就已经坏了，说明问题在资产本身，不在网页。

## 7.2 先只看骨架，不看材质

建议临时做两个对照：

1. 隐藏最终显示用的带材质模型
2. 只看会动的那套 Mesh

再看第 20 帧：

1. 如果白膜模型也一起脸部拉伸，说明是动作或骨架问题
2. 如果白膜模型正常，只有换材质后的最终模型拉伸，说明更像绑定/权重/修改器问题

## 7.3 检查第 20 帧有没有异常骨骼关键帧

重点看头脸相关骨骼：

1. 头骨
2. 下巴
3. 颈部
4. 眼睛
5. 任何面部控制骨

检查方式：

1. 选中主骨架
2. 进入 `Pose Mode`
3. 把时间轴停在第 20 帧
4. 在 `Dope Sheet -> Action Editor` 或 `Graph Editor` 里查看这一帧附近的关键帧

重点看：

1. 有没有某根骨骼突然偏转很大
2. 有没有不该出现的 `Scale` 关键帧
3. 有没有某根骨骼的 `Location / Rotation / Scale` 曲线在第 20 帧突然尖刺

经验上最值得先查的是：

1. 头部或颈部骨骼的缩放
2. 面部控制骨的缩放
3. 某根骨骼误打上的关键帧

## 7.4 优先删除“异常缩放关键帧”

脸被拉伸时，一个很常见的原因是：

1. 某根骨骼在第 20 帧存在非 `1,1,1` 的缩放

处理建议：

1. 在第 20 帧选中可疑骨骼
2. 看右侧变换数值里 `Scale` 是否异常
3. 如果异常，先把缩放改回 `1,1,1`
4. 再重新插帧或直接删除这根骨骼的缩放关键帧

如果你不确定该不该保留这组缩放键，当前项目建议是：

1. 面部和头部相关骨骼优先不要保留奇怪的缩放动画
2. 先让动作自然，再考虑精细表情

## 7.5 检查是否是权重问题被某个姿势放大了

如果第 20 帧时头部转动幅度一大，脸就被扯坏，常见原因是：

1. 面部顶点权重分配错误
2. 脸部顶点被错误分配给了头部以外的骨骼
3. 脖子、头、下巴、胸口之间的权重过渡不干净

排查方式：

1. 选中最终显示模型
2. 进入 `Weight Paint`
3. 分别查看头、颈、下巴附近相关骨骼的权重

如果某些脸部顶点被分到了不合理的骨骼上，就会在特定姿势出现“平时正常，某一帧突然爆掉”的现象。

## 7.6 检查 shape key / 约束 / 修改器残留

如果这个模型不是纯 Mixamo 骨骼链，也可能还有别的残留影响：

1. Shape Key
2. Constraint
3. 额外 Armature Modifier
4. 重复骨架影响

建议检查：

1. 模型是否有多个 `Armature Modifier`
2. 是否同时受两个骨架影响
3. 是否有表情 shape key 在第 20 帧被意外驱动

## 7.7 最快判断结论的方法

如果你想最快判断问题在哪一层，建议按下面顺序：

1. Blender 里切到第 20 帧，看是否已拉伸
2. 隐藏材质版最终模型，只看会动白膜模型
3. 若白膜也坏：查动作关键帧 / 骨骼缩放
4. 若白膜正常、材质版坏：查绑定 / 权重 / 修改器

## 8. 当前项目下的建议处理优先级

如果当前就是卡在“第 20 帧脸拉伸”，建议优先这样处理：

1. 先在 Blender 里确认第 20 帧是否已坏
2. 优先排查头脸相关骨骼的异常 `Scale`
3. 如果是单根骨骼误插关键帧，直接删掉这一帧附近的问题键
4. 如果是权重问题，再回到权重清理

当前不建议先怀疑网页代码，因为：

1. 我们前端这里只是正常播放 `GLB` 动画
2. 不会只精准把“第 20 帧脸拉伸”这种局部问题制造出来
3. 这种现象更像资产层问题被网页忠实播放出来

## 9. 修第 20 帧时，应该点“替换关键帧”，不是乱点“插入单个关键帧”

这一点非常容易混淆，这里单独说明。

### 9.1 什么时候用“替换关键帧”

如果当前情况是：

1. 这根骨骼本来就已经有动画
2. 第 `20` 帧本来就已经有一个关键帧
3. 你现在只是想把第 `20` 帧这个错误姿势改小一点

那么正确操作是：

1. 在第 `20` 帧把姿势调好
2. 在你刚改过的数值上右键
3. 选择 `替换关键帧`

这里的意思是：

1. 用你现在的新数值
2. 覆盖第 `20` 帧原来的旧数值

也就是说，这是“把错的第 20 帧改成新的第 20 帧”，不是额外再新建一套动作。

### 9.2 什么时候才用“插入单个关键帧”

`插入单个关键帧` 更适合下面这种情况：

1. 这个通道原本没有关键帧
2. 你现在是第一次给它打键
3. 或者你明确就是要新增一个新的关键帧

但当前“修第 20 帧嘴歪”的场景里，通常不是这个情况。

因为：

1. 第 `20` 帧本来就已经有动画
2. 你不是要加新动作
3. 你只是要改掉已经存在的坏姿势

所以优先理解成：

1. `替换关键帧` = 覆盖旧值
2. `插入单个关键帧` = 新增一个键

## 10. 不要把所有变红的都一起替换

还有一个常见误区：

1. 看到右侧一堆数值都变红
2. 就以为要全部一起替换

这通常不对。

正确原则是：

1. 只替换你刚刚实际改过的那一组
2. 没改过的不要乱替换

## 10.1 当前嘴歪问题优先改哪一组

如果当前是“脖子或头部转角太大，导致嘴歪”，优先检查和替换的是：

1. `旋转`

如果当前骨骼是四元数模式，你会看到的是：

1. `W`
2. `X`
3. `Y`
4. `Z`

这四项都属于“旋转”。

也就是说：

1. 如果你刚刚调的是脖子骨骼姿势
2. 就优先对 `旋转` 这一组做 `替换关键帧`
3. 不要先去乱动 `位置`
4. 也不要先去乱动 `缩放`

## 10.2 当前位置 / 旋转 / 缩放怎么判断该替换谁

可以按这个最简单的判断：

1. 如果你刚刚是按 `R` 调姿势，那么就替换 `旋转`
2. 如果你刚刚是按 `G` 挪位置，那么就替换 `位置`
3. 如果你刚刚是按 `S` 缩放，那么就替换 `缩放`

当前这个问题里，大多数时候先处理的是：

1. `旋转`

## 11. 当前项目下最短可执行操作

如果你现在就是在修第 `20` 帧的 `mixamorig:Neck`，建议按下面做：

1. 进入 `Pose Mode`
2. 选中 `mixamorig:Neck`
3. 时间轴停在第 `20` 帧
4. 用 `R` 把脖子姿势调到嘴巴不歪
5. 打开右侧 `N -> 项目 -> 变换`
6. 在 `旋转` 这一组的 `W / X / Y / Z` 数值上右键
7. 选择 `替换关键帧`

注意：

1. 这里不是“看到红色就全替换”
2. 而是“你刚刚改的是旋转，所以替换旋转这一组”

## 12. 一句话记忆

修坏掉的现有帧时：

1. 先改姿势
2. 再对改过的通道点 `替换关键帧`

不是所有时候都点 `插入单个关键帧`，也不是所有红色项目都要一起覆盖。

## 13. Blender 中文界面的“曲线编辑器”就是 `Graph Editor`

如果后续文档或对话里提到：

1. `Graph Editor`

那么在当前 Blender 中文界面里，对应的名字通常是：

1. `曲线编辑器`

也就是说：

1. `Graph Editor = 曲线编辑器`

不要因为菜单里看不到英文名就以为没有这个功能。

## 14. 当前已验证的动作衔接结论

这一轮已经明确验证出两个很关键的结论：

### 14.1 资产侧结论

如果想让：

1. `idle -> response -> idle`

看起来更自然，优先先做这件事：

1. 让 `response` 的首帧尽量接近 `idle`
2. 让 `response` 的尾帧也尽量回到接近 `idle`

当前已经验证：

1. 把 `response` 的前后一帧改得更接近 `idle` 后
2. 切换自然度会明显提升

### 14.2 代码侧结论

如果你已经确认：

1. `response` 本身没有额外抬手
2. 但结束回到 `idle` 时突然冒出一个不属于两边动作的怪姿势

那么优先怀疑：

1. 网页端的回切混合方式

当前项目已做的修正是：

1. 响应动作结束后，不再先 `stop()` 再切回 `idle`
2. 而是通过 `crossFade` 平滑回到 `idle`

所以后续遇到类似问题时，建议先判断：

1. 是资产首尾帧没接上
2. 还是代码侧回切方式不对
