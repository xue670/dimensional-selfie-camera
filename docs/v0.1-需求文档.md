# V0.1 需求文档

## 1. 版本目标

在手机端交付一个可运行的自拍合影原型，支持导入单个 2D 图片或 3D 模型角色，并与用户完成自拍导出。

## 2. 用户故事

1. 作为用户，我希望打开应用后直接进入自拍页面。
2. 作为用户，我希望切换或默认使用前置摄像头。
3. 作为用户，我希望导入一张透明底角色图，并把它摆到我身边合影。
4. 作为用户，我希望导入一个 3D 角色模型，并调整它在画面中的位置和大小。
5. 作为用户，我希望角色不是完全静止的，而是有一点呼吸感和陪伴感。
6. 作为用户，我希望点击拍照后能保存最终合影图片。

## 3. 功能需求

### F1. 相机预览

1. 打开页面后请求摄像头权限。
2. 默认优先调用前置摄像头。
3. 相机画面全屏显示。

### F2. 资产导入

1. 必须支持本地导入 PNG。
2. JPG 作为兼容输入格式，若实现成本过高可降级到后续小版本。
3. 必须支持本地导入 GLB。
4. GLTF 作为后续兼容增强项，不纳入 V0.1 强制验收。
5. 加载失败时给出明确提示。

### F3. 角色摆放

1. 角色可拖动。
2. 角色可缩放。
3. 角色可旋转。
4. 移动端手势优先。

### F4. 角色表现

1. 2D 角色具备轻微上下浮动。
2. 3D 角色具备轻微待机旋摆。
3. 导入后角色自动归中并校正到默认面朝用户/镜头。
4. V0.1 不要求实时头部追踪或面部跟随。

### F5. 拍照导出

1. 点击快门后合成相机画面与角色层。
2. 生成最终图片。
3. 必须支持图片保存或下载。
4. 系统分享作为兼容增强项，有条件时接入。

## 4. 非功能需求

1. 首屏 UI 在进入页面后应尽快可交互。
2. 在用户完成相机授权后，5 秒内进入可拍摄状态。
3. 主要交互适配竖屏手机。
4. UI 控件尽量少，避免遮挡主体画面。
5. 页面需支持 HTTPS 环境部署，以保证相机权限正常。
6. V0.1 默认本地处理拍摄与导入数据，不依赖服务端上传。

## 5. 版本边界

### 本版本包含

1. 单角色导入。
2. 照片模式。
3. 本地文件导入。
4. 基础动画。

### 本版本不包含

1. 视频录制。
2. 多角色。
3. 云端账号。
4. AI 对话。
5. 高级 AR 空间定位。

## 6. 验收标准

1. 在手机浏览器中能正常调起前摄。
2. 能导入至少 1 张 PNG 和 1 个 GLB 进行拍摄。
3. JPG 或 GLTF 如未在 V0.1 实现，不视为版本不通过。
4. 最终导出的图中包含相机背景和角色内容。
5. 角色操作在触屏上可完成。
6. 导入后角色默认处于可见范围内，并面朝用户/镜头。
