# Blender 多动画 GLB 制作指南

适用目标：

1. 你已经有一个角色模型
2. 你已经能把角色上传到 Mixamo
3. 你希望最后导出一个 `GLB`
4. 这个 `GLB` 里同时包含多条动画，例如：
   - `idle`（待机）
   - `response`（响应）

这份文档只讲一条最适合当前项目的路线：

1. 保留原始带材质 `GLB` 作为主角色
2. 从 Mixamo 分别下载多个动作 `FBX`
3. 在 Blender 里把动作转移到主角色骨架
4. 导出成一个带材质、带多条动画的 `GLB`

---

## 1. 最终你要得到什么

目标不是多个不同动画的 `GLB` 文件，而是：

1. 一个角色模型
2. 一个骨架
3. 多条动作
4. 正确保留原始材质
5. 一个最终导出的 `GLB`

推荐第一版只准备两条动作：

1. `idle`（待机）
2. `response`（响应）

等项目里的互动逻辑跑顺以后，再继续加：

1. `peace_response`
2. `touch_response`
3. `wave_response`

---

## 2. 先确认材质策略

你现在已经验证了一个非常关键的事实：

1. 原始 `GLB` 有材质
2. Mixamo 回来的 `FBX` 没材质

这说明当前最稳的流程不是：

1. 直接把 Mixamo 回来的文件当最终模型导出

而是：

1. 用原始带材质 `GLB` 做主角色
2. 用 Mixamo 的 `FBX` 只做动作来源

也就是说：

1. 材质来自原始 `GLB`
2. 动画来自 Mixamo `FBX`
3. 最后在 Blender 里合并成一个新的最终 `GLB`

这是这份文档后面所有步骤的前提。

---

## 3. Mixamo 下载阶段

### 2.1 先准备动作列表

建议先只选 2 个动作：

1. 一个待机动作
2. 一个回应动作

示例：

1. `idle`（待机）
2. `wave`（挥手）或 `happy idle`（开心待机）或 `look around`（左右看）

注意：

1. 不要第一轮就下载很多动作
2. 先保证一条待机 + 一条回应能跑通

### 2.2 下载设置建议

每个动作都单独下载一次。

建议下载格式：

1. `FBX`（一种常见的 3D/动画交换格式）

建议尽量保持一致的设置：

1. `Skin`: `With Skin`
2. 帧率保持默认即可
3. Keyframe Reduction 先保持默认

为什么建议 `FBX with skin`：

1. 对 Blender 导入更直观
2. 更适合你现在这条“同一个角色合并多个动作”的流程

### 2.3 你应该下载哪些文件

第一轮建议下载这两个：

1. `idle.fbx`
2. `response.fbx`

它们本质上都是：

1. 同一个角色
2. 同一个骨架结构
3. 不同的动作数据

## 4. Blender 合并思路

先理解一下核心原则：

1. 你最后场景里应该只保留一个主角色模型
2. 主角色模型应该来自原始带材质的 `GLB`
3. 只保留一个主骨架
4. Mixamo 导入文件的价值只是“把动作拿过来”
5. 不要把多个角色模型一起导出

简单理解就是：

1. 原始带材质 `GLB` 当主角色
2. Mixamo `FBX` 只是动作来源
3. 最后把 Mixamo 动作挂到主角色骨架上
4. 导出时只导出主角色

---

## 5. Blender 详细操作

以下步骤默认你已经打开 Blender。

### 5.1 新建一个干净场景

建议先新建一个专门做动作合并的文件。

操作建议：

1. 打开 Blender
2. `File -> New -> General`
3. 删除默认立方体、灯光、相机也可以，不删也行

如果想保持干净：

1. 框选默认对象
2. 按 `X`
3. 删除

### 5.2 先导入原始带材质 GLB，作为主角色

这是最重要的一步。

你现在的主角色不再用 Mixamo 下载回来的文件，而是你最初那个带材质的 `GLB`。

操作：

1. `File -> Import -> glTF 2.0 (.glb/.gltf)`（文件 -> 导入 -> glTF 2.0）
2. 选择原始带材质的 `GLB`
3. 导入

导入后你要先检查：

1. 角色材质是否正常
2. 贴图是否正常显示
3. 模型朝向是否正常

如果这一步材质不正常，先不要往下做动作合并，先把材质问题解决。

建议立刻保存工程：

1. `File -> Save As`（文件 -> 另存为）
2. 比如保存成：`character_with_materials.blend`

### 5.3 再导入第一个动作文件

先导入 `idle.fbx`。

操作：

1. `File -> Import -> FBX (.fbx)`（文件 -> 导入 -> FBX）
2. 选择你的 `idle.fbx`
3. 导入

导入后你通常会看到：

1. 一个角色 Mesh
2. 一个 Armature
3. 时间轴上有动作

这个导入进来的角色通常是白膜或没有原材质，但没关系，因为它只是动作来源。

### 5.4 给第一个动作改名

这一步非常重要，不然后面动作容易都叫一堆默认名。

操作：

1. 选中 `Armature`
2. 打开下方时间轴区域，切到 `Dope Sheet`（中文界面通常叫“动画摄影表”）
3. 再切到 `Action Editor`（中文界面通常叫“动作编辑器”）
4. 在动作名位置找到当前动作
5. 把它改名为：

`idle`（待机）

建议命名简单直接：

1. `idle`（待机）
2. `response`（响应）
3. 以后扩展 `peace_response`

### 5.5 导入第二个动作文件

再导入 `response.fbx`。

操作：

1. `File -> Import -> FBX (.fbx)`（文件 -> 导入 -> FBX）
2. 选择第二个动作文件
3. 导入

这时场景里通常会多出：

1. 第二个角色 Mesh
2. 第二个 Armature
3. 第二条动作

先别急着删。

### 5.6 找到第二个文件里的动作

操作：

1. 选中第二个 `Armature`
2. 打开 `Dope Sheet -> Action Editor`（动画摄影表 -> 动作编辑器）
3. 找到它当前绑定的动作
4. 先把这个动作重命名为：

`response`（响应）

这一步的目的：

1. 先把动作保存成明确名字
2. 后面即使删掉第二个模型，也不容易分不清

### 5.7 确认动作已经成为独立 Action

关键点：

Blender 的动作如果没有“保留”，有时可能在清理对象后丢失。

你要做的是：

1. 在 `Action Editor`（动作编辑器）里找到动作名
2. 确认这个动作被保存
3. 能的话给它点上保留标记

你要确保最后至少能在动作列表里看到：

1. `idle`（待机）
2. `response`（响应）

### 5.8 关键分叉：原始 GLB 没骨架，还是已经有骨架

这里要先判断你的原始带材质 `GLB` 当前是什么状态：

1. 只有模型，没有骨架
2. 已经有骨架，但不是 Mixamo 那套动画骨架
3. 已经是同一套可复用骨架

对于大多数当前场景，最常见的是：

1. 原始带材质模型没有最终可复用的 Mixamo 动画骨架

这时最稳妥的做法通常不是“直接把动作切给原始模型”，而是：

1. 用 Mixamo 的骨架作为动画主骨架
2. 把原始带材质 Mesh 绑定到这套骨架
3. 再让这套骨架播放多条动作

所以后面你要做的其实是：

1. 保留原始带材质 Mesh
2. 保留 Mixamo 的主 Armature
3. 让原始 Mesh 跟随 Mixamo Armature

### 5.9 最稳妥方案：把原始材质模型绑定到 Mixamo 主骨架

这一段是这条流程的核心。

目标：

1. 原始 `GLB` 负责材质和最终显示
2. Mixamo `FBX` 提供骨架和动作
3. 最终角色看起来有原材质，同时能播 Mixamo 动画

思路通常是：

1. 选择原始带材质模型
2. 把它绑定到 Mixamo 的主 `Armature`
3. 用 Mixamo `Armature` 作为最终动作控制器

常见做法：

1. 保留原始模型 Mesh
2. 保留第一个 Mixamo 文件的 `Armature`
3. 删除或隐藏 Mixamo 白膜 Mesh
4. 让原始材质模型使用这个 Mixamo Armature

如果你的角色拓扑和 Mixamo 上传的是同一个模型来源，这一步通常是可行的。

最常见绑定方式是：

1. 选中原始带材质 Mesh
2. 再选中 Mixamo 的 `Armature`
3. 按 `Ctrl + P`
4. 选择合适的父级方式

常见选项包括：

1. `With Automatic Weights`（使用自动权重）
2. `Armature Deform`（骨架变形）

如果你的原始模型和上传 Mixamo 的模型本来就是同一个角色来源，通常能直接用。

完成后测试：

1. 选中 Mixamo `Armature`
2. 播放 `idle`（待机）
3. 看原始带材质模型是否会跟着动

如果原始带材质模型已经能跟着这个 Armature 正常动，说明最难的部分已经过了。

### 5.9A 如果原始材质模型绑不上骨架，改走“给会动白膜模型换材质”

如果你已经验证出：

1. Mixamo 白膜模型会动
2. 原始带材质模型挂了 `Armature` 修改器也不动

那么当前更稳的路线是：

1. 保留会动的 Mixamo 模型
2. 不再继续死磕原始模型重新绑定
3. 直接把原始材质切换到会动的白膜模型上

操作步骤：

1. 在 `Outliner` 里选中会动的白膜模型
2. 打开右侧材质面板
3. 在材质槽列表里选中当前槽位
4. 点击当前材质名左边的小白球下拉按钮
5. 从材质列表中切换到原始材质

关键截图说明：

![材质切换示意图](C:/Users/41799/Documents/New%20project/docs/assets/blender-材质切换示意.png)

图里要点：

1. 上方红框：先确认当前材质槽已经选中
2. 下方红框：点击小白球下拉按钮
3. 在弹出的材质列表中，选择原始模型对应的材质名

成功后的预期：

1. 白膜模型开始显示原始颜色和贴图
2. 播放 `idle` 时，会动的仍然是 Mixamo 模型
3. 但视觉上已经不再是白膜

### 5.10 把 response 动作绑定到主骨架测试

现在开始关键验证。

这里的“主 `Armature`”指的是最终你保留下来的 Mixamo 主骨架。

操作：

1. 选中最终保留的主 `Armature`
2. 打开 `Action Editor`（动作编辑器）
3. 在动作下拉列表中切换
4. 选择 `response`（响应）

如果动作切过去后，主角色也能正常动，说明成功了。

这是最关键的一步。

成功标准：

1. 你只选主骨架
2. 切到 `response`
3. 原始带材质角色能正常播放动作

如果这一步成功，就说明两个动作已经能共用同一个角色骨架。

### 5.11 删除或隐藏多余的白膜模型

当你确认主骨架已经能播放：

1. `idle`（待机）
2. `response`（响应）

这时就可以删掉第二次导入的那套对象。

删除或隐藏目标通常是：

1. 多余的 Mixamo 白膜 Mesh
2. 第二次导入文件里不用的白膜 Mesh

注意：

1. 不一定要删主 Mixamo `Armature`
2. 因为主 Mixamo `Armature` 很可能就是你最终的动画骨架
3. 真正该删的通常是“多余的白膜 Mesh”，不是最终动作骨架

注意：

1. 删之前先确认主骨架动作切换没问题
2. 删掉后再测一次 `idle` 和 `response`

删完后，场景里理想状态应该只剩：

1. 一个最终显示用的带材质角色 Mesh
2. 一个主 Armature
3. 多条动作

### 5.12 再次验证动作切换

在导出前一定做一次最终检查。

操作：

1. 选中主 `Armature`
2. 在 `Action Editor`（动作编辑器）里切换到 `idle`（待机）
3. 播放看是否正常
4. 再切到 `response`（响应）
5. 播放看是否正常

如果都正常，说明合并完成。

## 6. 导出 GLB

### 6.1 导出前检查

导出前请确认：

1. 场景里只剩一个角色和一个主骨架
2. 最终显示的是带材质角色，不是白膜 Mixamo Mesh
3. 主骨架可以切换 `idle`
4. 主骨架可以切换 `response`
5. 模型朝向和比例正常

### 6.2 导出操作

操作：

1. `File -> Export -> glTF 2.0`（文件 -> 导出 -> glTF 2.0）
2. 文件格式选：

`glTF Binary (.glb)`

### 6.3 导出设置建议

建议重点检查以下项：

1. `Format`: `glTF Binary (.glb)`
2. 勾选导出动画
3. 如有 `Include -> Selected Objects`（包含 -> 仅选中对象），确认你选的是正确主角色对象

不同 Blender 版本界面略有不同，但核心就是：

1. 导出成 `.glb`
2. 动画要导出去

### 6.4 导出命名建议

建议文件名也清晰一点，例如：

1. `character_idle_response.glb`
2. `gintoki_companion_v1.glb`

---

## 7. 导入到当前项目后的预期

如果导出正确，当前项目里导入后应出现以下行为：

1. 页面提示会显示当前识别到的待机动作名
2. 如果识别到另一条动作，也会显示互动动作名
3. 点击“互动一下”时，会优先播放 `response`（响应）
4. 播放结束后回到 `idle`（待机）

## 8. 推荐命名规范

为了减少后面网页识别的歧义，建议你以后统一用这个命名：

### 最小版本

1. `idle`（待机）
2. `response`（响应）

### 后续扩展版

1. `idle`（待机）
2. `peace_response`（比耶响应）
3. `touch_response`（触碰响应）
4. `wave_response`（挥手响应）

命名建议：

1. 全英文
2. 小写
3. 下划线分隔
4. 不要太长

## 9. 常见问题

### 8.1 为什么我导出的是多个角色，而不是多个动作

原因通常是：

1. 你把多个导入角色都一起留在场景里了
2. 但没有把动作真正挂回主骨架

解决思路：

1. 先测试主骨架是否能切换到另一个动作
2. 能切成功后，再删第二套角色

### 9.1 为什么 Mixamo 回来的文件是白膜

这通常是正常现象。

原因一般是：

1. Mixamo 主要提供骨骼和动画，不可靠保留原始 `GLB` 材质
2. `GLB -> Mixamo -> FBX` 这条链路里，PBR 材质经常丢失
3. 有时材质槽还在，但贴图路径断掉了

当前项目的推荐处理方式不是修白膜，而是：

1. 原始 `GLB` 保材质
2. Mixamo `FBX` 只拿动作和骨架

### 9.2 为什么动作名还是奇怪的 `Armature|mixamo.com|Layer0`

因为 Mixamo/FBX 导进 Blender 后经常会保留默认命名。

解决：

1. 在 `Action Editor`（动作编辑器）里手动改名
2. 改成 `idle`（待机） / `response`（响应）

### 9.3 为什么网页里还是只播放一条动作

可能原因：

1. 导出时动画没导出去
2. 场景里动作没有正确保留下来
3. 两条动作实际上没有都挂到主骨架

排查顺序建议：

1. 在 Blender 里切主骨架的 `Action`（动作），看能不能切到另一条
2. 确认导出时勾了动画
3. 再导入网页测试

### 9.4 我原始 GLB 有材质，但绑定到 Mixamo 骨架后不动怎么办

这通常说明以下某一步还没对上：

1. 原始材质 Mesh 没有正确父级到 Mixamo `Armature`
2. 权重没有正确建立
3. 你播放的是另一个不再使用的骨架

排查顺序建议：

1. 只保留一个主 `Armature`
2. 播放这个 `Armature` 的动作
3. 观察原始带材质模型是否跟着变形
4. 如果不动，重新检查绑定方式

### 9.5 我现在只会做一个 idle，够不够

够你继续当前项目。

当前最小可用资产是：

1. 一个带 `idle`（待机）的 `GLB`

更适合进入互动版本的是：

1. 一个带 `idle`（待机）
2. 一个带 `response`（响应）

---

## 10. 当前项目建议路线

基于现在的项目状态，建议你这样推进：

1. 先保留原始带材质 `GLB`
2. 再从 Mixamo 下一个最简单的 `idle`（待机）和 `response`（响应）动作 `FBX`
3. 在 Blender 里保留原材质模型
4. 用 Mixamo 骨架驱动原材质模型
5. 把 `idle + response`（待机 + 响应）都挂到同一个主骨架
6. 导出一个带材质、带多动作的 `GLB`
7. 再导入当前项目测试互动

第一轮不要追求太复杂，先把这一版跑通最重要。
