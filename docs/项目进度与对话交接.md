## 6. V0.2 当前已做内容

当前未提交代码里，已经做了第一轮互动原型：

### 6.1 陪伴位

已新增：

- `左下陪伴位`
- `右下陪伴位`
- `自由摆放`

并且陪伴位已经加入：

- 更靠近镜头的 `depth`
- 前倾 `tilt`
- 轻微歪斜 `roll`

目标是让角色更像从画面边缘探进来一起自拍。

### 6.2 左下陪伴位位置修正

用户实测后给出的结论：

- “左下陪伴位 + 点击 2 下下移，1 下左移，1 下放大之后的位置更适合”

当前代码已经把这个结果固化为新的左下陪伴位默认值，并同步调整了右下陪伴位的对称位置。

### 6.3 微调与陪伴位关系修复

之前存在的问题：

- 用户点完陪伴位后，再点微调按钮，会自动退出陪伴位模式
- 导致手动微调结果和预设不一致

当前已经修复为：

- 微调时不再自动退出陪伴位
- 可以在同一个透视基础上继续细调

### 6.4 互动按钮

当前已新增：

- `互动一下`

当前逻辑：

1. 优先播放模型里的响应动作
2. 如果没有合适响应动作，则回退到轻量假动作
3. 响应结束后自动回到 `idle`
4. 当前代码已改为通过 `crossFade` 平滑回到 `idle`，而不是先硬 `stop()` 再切回
5. 当前已接入三种触发方式：
   - 按钮触发
   - 点一下角色区域触发
   - 挥手触发（演示级本地检测）

用户当前反馈：

- “互动确实互动了，就是很呆，跳了一下”

因此目前状态是：

- 互动链路已通
- 角色感仍不自然
- 新一轮代码已开始把 fallback 从“整段弹一下”调整为更像点头靠近镜头的回应
- 已确认“response 结束瞬间出现一小段怪抬手”主要是回切混合方式导致，不是资产里多了一段未知动作
- 挥手触发已能跑通，但当前实现仍属于 demo 级轻量检测，后续可继续优化灵敏度和误触控制

### 6.5 互动状态方向

当前已经对齐的后续正确方向：

`idle -> 用户动作触发 -> response animation -> idle`

也就是说：

1. 正常状态始终播放 `idle`
2. 用户动作触发后切到响应动画
3. 响应结束自动回到 `idle`

## 7. Blender / 资产路线当前结论

## 7.1 用户当前资产制作方式

用户当前是基于 Mixamo 获取带动画的模型：

1. 原始 `GLB` 有材质
2. 导入 Mixamo 后下载回来的 `FBX` 没材质，呈现“白膜”

当前结论已经明确：

- 丢材质主要发生在 `GLB -> Mixamo -> FBX` 这条链路

## 7.2 多动画 GLB 的推荐目标

最终推荐的网页资产形式仍然是：

1. 一个角色
2. 一个骨架
3. 多条动画
4. 一个最终 `GLB`

建议至少具备：

1. `idle`
2. `response`

## 7.3 当前 Blender 关键术语（中文界面）

已经确认用户使用 Blender 中文界面，因此文档中需要保留中英对照：

- `Dope Sheet（动画摄影表）`
- `Action Editor（动作编辑器）`
- `With Automatic Weights（使用自动权重 / 附带自动权重）`

## 7.4 当前动画命名进展

用户已在 Blender 中完成：

1. 第一条动作改名为 `idle`
2. 第二条动作显示为 `thoughtfulheadnod`
3. 已验证把 `response` 的前后一帧尽量对齐 `idle` 后，动作切换明显更自然

说明：

- 多动作来源已经具备初步基础
- 当前网页侧已经把 `thoughtfulheadnod` 识别为可用响应动作候选

## 7.5 原始带材质模型重新绑定骨架的尝试结果

已尝试路线：

1. 原始带材质模型没有骨架
2. 将其通过 `Ctrl + P -> 附带自动权重` 绑定到 Mixamo 的 `Armature`
3. 原始模型上也确实出现了 `Armature` 修改器

但实测结果：

- 播放 `Armature` 的 `idle` 时，原始带材质模型没有正常跟着动

因此当前结论是：

- 暂不继续深挖“原始模型重新自动绑骨架”这条路

## 7.6 当前更推荐的路线

现在更推荐：

1. 保留会动的 Mixamo 白膜模型
2. 保留会动的 `Armature`
3. 尝试把原始模型的材质切换到会动的白膜模型上

也就是：

- 用“会动的模型”做主模型
- 把“原始材质”迁移过去

这是当前最适合快速做出 demo 的路线。

## 9. 当前最重要的用户反馈

### 9.1 关于互动效果

用户当前更在意的不是“会不会动”，而是：

- 能不能更像角色在回应

已对齐的重点：

1. 互动最终应基于真实动画状态切换
2. 不是长期停留在“整体跳一下”的 fallback
3. 若切换不自然，优先先检查 `response` 首尾姿势是否接近 `idle`

### 9.2 关于功能优先级

用户明确要求：

1. 当前优先实现社媒可演示的互动效果
2. 不是优先补全所有稳定性问题
3. 除非会影响后续架构，否则效果优先
